# CheckMate / 不要成为咸鱼

> 一个带桌面宠物、任务提醒、重复提醒、倒计时、宠物养成、设置中心和数据安全保护的本地打卡督促小程序。
> 今天也别悄悄变成咸鱼。

CheckMate 是一个使用 **Python + PySide6 + SQLite** 开发的 Windows 桌面端效率工具。

它的核心目标是：

- 管理每日任务和长期习惯
- 到点提醒用户完成任务
- 支持重复提醒、稍后提醒、今天不再提醒
- 支持专注倒计时
- 关闭主窗口后仍在系统托盘后台运行
- 通过桌面宠物进行陪伴和督促
- 完成任务后获得宠物经验
- 通过升级、进化、历史记录和统计反馈形成正向激励
- 通过设置页面统一管理常规设置、提醒设置、宠物设置、数据管理、外观设置和关于信息
- 尽量保护本地数据不因更新、误删、覆盖或异常修改而丢失

---

## 项目定位

CheckMate 不是复杂的项目管理软件，也不是团队协作工具。

它更像是一个个人桌面陪伴型打卡工具：

- 到点提醒你该做事
- 完成任务后给宠物加经验
- 宠物会升级、进化
- 桌面宠物会通过状态和语录督促你
- 关闭窗口后仍能在系统托盘后台运行
- 用户数据保存在本地，不依赖账号和云服务

一句话：

> 你完成任务，宠物成长；你一直拖延，宠物陪你变咸。

### 每日打卡

* 每日任务打卡
* 今日完成统计
* 连续打卡天数统计
* 本月完成率统计

* 历史记录中，重复提醒任务只要当天完成过至少一次，就显示为已完成

### 完成 / 撤销打卡规则

CheckMate 当前的打卡按钮会根据任务状态自动切换显示文字。

| 当前任务状态            | 按钮文字 | 点击后的行为                            |
| ----------------------- | -------- | --------------------------------------- |
| 未完成的普通任务 / 习惯 | 完成打卡 | 写入当天 `checkins`，任务变为已完成     |
| 已完成的普通任务 / 习惯 | 撤销打卡 | 弹出确认窗口，确认后删除当天 `checkins` |
| 重复提醒任务            | 完成打卡 | 完成本轮任务，并重新安排下一次提醒      |
| 暂停任务                | 完成打卡 | 不允许打卡，会提示任务已暂停            |

撤销打卡流程：

```text
点击“撤销打卡”
↓
弹出确认窗口
↓
Yes：删除当天 checkins 记录，任务变为未完成
No：不做任何处理
```

注意：

```text
撤销打卡目前只影响当天 checkins 记录。
不会回退宠物经验。
不会回退宠物等级。
不会删除历史中其他日期的打卡记录。
```

这样设计是为了避免撤销时牵连宠物升级、进化、连续打卡奖励等复杂回滚逻辑。

## 每日刷新规则

CheckMate 使用 `task_date` 表示任务当前属于哪一天。

```text
created_at：
    真实创建时间，不随每日刷新改变。

task_date：
    当前任务属于哪一天。
    每日刷新时会根据任务类型、完成状态和暂停状态更新。
```

每日 0 点或程序启动时会执行刷新。

当前规则：

| 类型       | 状态           | 第二天行为                             |
| ---------- | -------------- | -------------------------------------- |
| 习惯 habit | 不管完成与否   | 更新到今天，继续显示                   |
| 习惯 habit | 暂停中         | 更新到今天，继续显示，并保持暂停       |
| 任务 task  | 启用中，已完成 | 归档，不再显示到今日任务               |
| 任务 task  | 启用中，未完成 | 顺延到今天，继续显示                   |
| 任务 task  | 暂停中         | 不管完成与否，都顺延到今天，并保持暂停 |
| 已归档任务 | 任意状态       | 跳过，不再处理                         |

规则总结：

```text
习惯每天自然刷新；
暂停项全部顺延；
一次性任务未完成则顺延；
一次性任务完成后归档；
已归档任务只保留给历史记录；
顺延到今天的任务，在今天统一表现为未完成。
```

说明：

```text
每日刷新只更新 tasks.task_date / is_archived。
不会删除 checkins。
不会给今天自动创建 checkins。
因此，顺延到今天的任务，今天天然是未完成状态。
```

## 历史记录规则

历史记录不按 `task_type`、`is_archived`、`is_active` 额外过滤。

只要一个任务在某一天“存在过”，就应该出现在那一天的历史记录中。

存在区间：

```text
habit：
    从 created_at 到今天都存在。

task：
    从 created_at 到 task_date 都存在。
```

示例：

```text
一次性任务 5 月 1 日创建，5 月 3 日才完成：
    5 月 1 日：显示未完成
    5 月 2 日：显示未完成
    5 月 3 日：显示已完成
    5 月 4 日：不再显示
```

完成状态由 `checkins` 表决定。

```text
某任务某天有 checkins：
    历史记录显示已完成。

某任务某天没有 checkins：
    历史记录显示未完成。
```

重复提醒任务只要当天至少完成过一次，历史记录中当天就显示为已完成。

## 重复提醒

任务或习惯可以设置重复提醒间隔。

例如：

* 每隔 30 分钟
* 每隔 1 小时
* 每隔 2 小时
* 每隔 4 小时
* 自定义，例如 `1h30min`、`45min`、`2h`

重复提醒任务的特点：

```text
到点提醒
↓
用户完成本轮
↓
宠物获得经验
↓
记录今天至少完成过一次
↓
以当前完成时间为起点，重新安排下一轮提醒
```

重复提醒任务不会因为当天已经打卡而停止后续提醒。

重复提醒任务和普通任务最大的区别是：

```text
普通任务：
    今天完成一次后，不再允许重复完成。
    再次点击按钮会进入“撤销打卡”流程。

重复提醒任务：
    今天完成一次后，仍然允许继续点击“完成打卡”。
    每次点击都表示“完成当前这一轮”。
    每天只需要至少写入一条 checkins，用于统计和历史记录。
```

如果重复提醒任务提前完成，下一次提醒时间会以“当前点击完成的时间”为新的起点。

示例：

```text
重复间隔：30 分钟

原本下一次提醒：10:40
用户在 10:25 提前点击完成
↓
旧的 10:40 提醒被取消
新的下一次提醒：10:55
```

原则：

```text
同一个 task_id 同一时间只允许存在一个活跃提醒计时器。
提前完成、稍后提醒、重复提醒之间不能产生多条提醒链路。
```

## 稍后提醒与重复提醒规则

如果重复提醒任务选择“稍后提醒”，稍后提醒时间会成为新的重复提醒起点。

示例：

```text
原提醒时间：09:00
重复间隔：1 小时

09:00 弹出提醒
用户选择 30 分钟后提醒
↓
09:30 再次提醒
用户点击完成
↓
下一次提醒变为 10:30
```

如果用户在稍后提醒到来之前，手动提前完成任务，则旧的稍后提醒会被取消，并以当前完成时间重新计算下一次提醒。

示例：

```text
原提醒时间：09:00
重复间隔：1 小时

09:00 弹出提醒
用户选择 30 分钟后提醒
↓
下一次提醒临时变为 09:30

用户在 09:10 手动点击“完成打卡”
↓
旧的 09:30 稍后提醒被取消
新的下一次提醒变为 10:10
```

原则：

```text
同一个 task_id 同一时间只允许存在一个活跃提醒计时器。
稍后提醒会接管提醒链。
提前完成会重置提醒链。
重复提醒会从最新一次完成时间继续计算。
```

## 打包方式

项目提供自动打包脚本：

```text
build_exe.py
```

运行：

```bash
python build_exe.py
```

当前推荐使用 `--onedir` 模式，因为 PySide6 和图片 / GIF / 音频资源较多，`onedir` 模式更稳定，也更方便排查资源路径问题。

打包结果默认输出到：

```text
release/
├── CheckMate.lnk
└── CheckMate/
    ├── CheckMate.exe
    ├── _internal/
    └── ...
```

说明：

* `CheckMate.exe` 使用 `checkmate_icon.ico`
* `CheckMate.lnk` 使用 `checkmate_shortcut_icon.ico`
* 如果只有 PNG，打包脚本会尝试用 Pillow 自动生成对应 ICO
* 快捷方式由 `pywin32` 创建
* 快捷方式是用户友好的启动入口，真正的程序本体仍然是 `CheckMate/CheckMate.exe` 及其依赖文件
* 重新运行 `build_exe.py` 时，通常会重新生成 release 目录和快捷方式
* `assets/` 会整体打包
* `assets/sounds/reminders/` 会随 `assets/` 一起打包
* 打包脚本会检查 release 中是否包含提醒音效目录和音频文件

发布时建议压缩整个 release 内容，不要只单独发送 `CheckMate.exe` 或 `CheckMate.lnk`。

## 数据存储位置

CheckMate 的用户数据不会直接保存在程序目录中，而是保存在当前用户的本地应用数据目录。

Windows 下默认路径：

```text
%LOCALAPPDATA%\CheckMate\
```

实际示例：

```text
C:\Users\用户名\AppData\Local\CheckMate\
```

目录结构：

```text
%LOCALAPPDATA%\CheckMate\
├── config.json
├── data/
│   └── checkmate.db
├── data_backups/
│   ├── auto_checkmate_xxx.db
│   ├── suspicious_checkmate_xxx.db
│   ├── before_restore_checkmate_xxx.db
│   ├── integrity.json
│   └── migration_done.txt
└── logs/
    └── data_guard.log
```

这样即使用户更新、删除或替换程序目录，任务、习惯、打卡记录、宠物进度和用户配置也不会被一起删除。

## 数据库设计

当前主要包含三类表：

```text
tasks
checkins
pet_status
```

---

### `tasks`

任务表，用于保存任务和习惯信息。

字段示意：

```text
id
title
description
remind_time
repeat_interval_minutes
task_type
is_archived
is_active
created_at
task_date
```

| 字段                      | 含义                                              |
| ------------------------- | ------------------------------------------------- |
| `id`                      | 任务 ID                                           |
| `title`                   | 任务名称                                          |
| `description`             | 任务备注                                          |
| `remind_time`             | 提醒时间，可为空                                  |
| `repeat_interval_minutes` | 重复提醒间隔，可为空                              |
| `task_type`               | 类型，`task` 表示一次性任务，`habit` 表示长期习惯 |
| `is_archived`             | 是否归档，0 表示未归档，1 表示已归档              |
| `is_active`               | 是否启用，0 表示暂停，1 表示启用                  |
| `created_at`              | 真实创建时间                                      |
| `task_date`               | 当前任务属于哪一天                                |

---

### `checkins`

打卡记录表，用于保存每日打卡记录。

字段示意：

```text
id
task_id
checkin_date
checkin_time
```

| 字段           | 含义         |
| -------------- | ------------ |
| `id`           | 打卡记录 ID  |
| `task_id`      | 对应任务 ID  |
| `checkin_date` | 打卡日期     |
| `checkin_time` | 具体打卡时间 |

同一个普通任务 / 普通习惯在同一天只能打卡一次。

重复提醒任务一天可以完成多轮，但 `checkins` 表中同一天仍然只记录一条完成记录。

也就是说：

```text
重复提醒任务第一次完成：
    写入当天 checkins。

重复提醒任务当天再次完成：
    不重复写入 checkins。
    但仍然会给宠物增加经验，并重新安排下一次提醒。
```

`checkins` 的作用是记录“某个任务在某一天是否至少完成过一次”，历史记录和每日刷新都会基于它判断完成状态。

---

### `pet_status`

宠物状态表，用于保存当前宠物的成长数据。

字段示意：

```text
id
pet_name
skin
level
exp
stage
mood
total_tasks_done
created_at
updated_at
```

| 字段               | 含义                           |
| ------------------ | ------------------------------ |
| `id`               | 固定为 1，第一版只支持一只宠物 |
| `pet_name`         | 宠物名称                       |
| `skin`             | 宠物皮肤，例如 `salty_fish`    |
| `level`            | 宠物等级                       |
| `exp`              | 当前等级内经验                 |
| `stage`            | 当前进化阶段                   |
| `mood`             | 当前心情 / 状态                |
| `total_tasks_done` | 累计完成任务数                 |
| `created_at`       | 创建时间                       |
| `updated_at`       | 更新时间                       |

## 数据安全机制

CheckMate 当前包含一套本地数据安全保护机制，位于：

```text
data_guard/
```

目标不是做到绝对防破解，而是做到：

* 普通用户不容易误删数据
* 程序更新不容易覆盖数据
* 数据库被外部修改后能检测出来
* 出问题后可以从备份恢复
* 可疑数据库不会被自动登记为正常数据库

---

### 自动备份

程序启动时可自动备份数据库：

```text
auto_checkmate_xxx.db
```

默认保存在：

```text
%LOCALAPPDATA%\CheckMate\data_backups\
```

自动备份开关和保留数量可在设置页面中管理：

```text
设置 → 数据管理
```

---

### 完整性校验

程序会计算当前数据库的 SHA256，并保存到：

```text
integrity.json
```

下次启动时重新计算数据库 hash，如果不一致，说明数据库可能被外部修改或损坏。

---

### 可疑数据库备份

检测到数据库异常时，会生成：

```text
suspicious_checkmate_xxx.db
```

并且不会刷新 `integrity.json`，避免把可疑数据库“洗白”。

---

### 恢复前备份

从备份恢复数据库前，会先保存当前数据库：

```text
before_restore_checkmate_xxx.db
```

这样即使恢复错了，也可以找回恢复前的数据。

---

### 数据迁移

旧版本数据库曾位于：

```text
CheckMate/data/checkmate.db
```

现在正式数据库位于：

```text
%LOCALAPPDATA%\CheckMate\data\checkmate.db
```

程序启动时会自动检查旧数据库是否存在，并在需要时迁移到 AppData 用户数据目录。

## UI 窗口稳定性规范

为了避免窗口拖动或重绘时出现控件压缩、文字变形，后续所有弹窗建议遵守：

```text
1. 外层窗口固定尺寸
2. 内部卡片固定尺寸
3. QLabel 设置固定高度或最小 / 最大高度
4. QPushButton 设置固定高度
5. Layout 设置 SetFixedSize
6. 不依赖 padding 单独撑开按钮高度
7. 弹窗显示时主动居中
```

常用写法：

```python
self.setFixedSize(440, 300)
self.setMinimumSize(440, 300)
self.setMaximumSize(440, 300)
```

按钮高度：

```python
button.setFixedHeight(38)
```

布局固定：

```python
layout = self.layout()
if layout is not None:
    layout.setSizeConstraint(QVBoxLayout.SizeConstraint.SetFixedSize)
```

弹窗居中：

```python
def showEvent(self, event):
    super().showEvent(event)
    QTimer.singleShot(0, lambda: center_dialog(self))
```

## 项目原则

1. 先完成功能闭环，再逐步美化 UI。
2. 每个文件只负责一类功能。
3. 数据库逻辑和界面逻辑分离。
4. 弹窗 UI 和提醒业务逻辑分离。
5. 宠物成长规则和宠物窗口显示分离。
6. 数据安全逻辑和业务功能分离。
7. 桌面宠物作为增强体验，不影响核心打卡功能。
8. 本地优先，不依赖账号和云服务。
9. 保持项目轻量，适合作为桌面应用练手项目。
10. 核心规则变更后，优先补充测试脚本，避免功能回退。
